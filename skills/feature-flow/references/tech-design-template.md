# 技术方案模板

标准功能可在任务记录中简述，高风险变更展开相关部分。无关项写“不涉及”或省略，不为填模板新造需求。事实原稿的位置由项目规定，评审平台引用原稿。

## 目标与验收（均需说明）

- 谁在什么起点想完成什么；当前问题与本次范围、非目标。
- 可观察的完成标准；主路径、失败恢复、回归与证据点。
- 风险等级及理由，采用的项目规则和已有授权。
- 用户界面：配置归属、可预期结果、反馈与恢复；按 [product-design-review](../../product-design-review/SKILL.md) 检查。

## 实现与合同（按影响展开）

- 最小可行方案、职责边界、数据流；关系复杂时配图。
- 关键合同、输入输出、错误语义、权限和消费者；兼容性变化先明确迁移路径。
- 涉及的数据模型、查询、迁移、实际数据库版本；性能证据要求见 [数据库规范](../../dev-standards/db-conventions.md)。
- 前端组件和状态归属；跨页、账号和工作区切换如何保持或隔离。
- 关键假设、重难点与证据；确有取舍再比较备选方案。

## 验证与交付（均需说明，深度与风险相称）

- 开发同步运行哪些测试，如何验证用户任务与模块组合。
- 现有证据及尚未验证的环境，阻塞哪一步、如何补齐。
- 交付边界：仅代码/合入/真实联调/部署；各自的通过条件。
- 如需上线：候选版本、发布顺序、监控、回退触发条件及执行人。
- 如涉及迁移：实际共存和可回退的应用版本矩阵、迁移顺序、备份/恢复、不可逆部分；不笼统写“兼容两个版本”。
- 并行任务的负责人、改动边界、依赖合同、集成顺序和组合验证。
