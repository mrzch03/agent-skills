# 方案评审清单

深度按 [风险等级](../../dev-standards/dev-flow.md) 决定。标准功能可简要自检；高风险项由项目指定负责人核对。角色由项目安排，不固定要求三方到场。

| 维度 | 要核对的证据 |
| --- | --- |
| 目标与范围 | 用户任务、非目标、可观察验收结果；方案是否解决根因 |
| 产品交互 | 任务入口、配置归属、即时反馈、失败恢复及上下文隔离 |
| 合同与架构 | 职责和依赖、消费者、版本兼容、权限边界 |
| 可行性 | 关键假设有 POC、事实或已有先例；未验证项明确影响哪一步 |
| 数据与性能 | 引擎版本、规模、频率、查询与锁成本；按数据库规范取证 |
| 验证设计 | 实现前已有测试场景，覆盖成功、失败、恢复及组合行为 |
| 交付与恢复 | 必要的发布顺序、迁移、回退条件和证据；未授权动作不默认执行 |

## 结论

输出“通过 / 需修改 / 证据不足”，列明阻塞项、理由、负责人或补齐方式。建议项与阻塞项分开。项目若要求评分或审批，使用其规则；不凭字母分数替代问题分析。
未解决的阻塞项不进入其依赖步骤；不相关的工作可以继续。关键业务取舍与发布授权由用户或项目负责人决定，技术评审不替代授权。
