# PostgreSQL 检查要点

先记录服务端版本、统计信息和测试数据规模。此页依据 PostgreSQL 18 文档核对（2026-11-10），其他版本按实际文档确认。

- 从 `EXPLAIN` 查看计划形态与估算；需要实际耗时及 I/O 证据时，在获准的隔离环境使用 `EXPLAIN (ANALYZE, BUFFERS)`。
- `ANALYZE` 会真正执行语句。即使随后回滚，也不能假设序列或外部副作用被撤销；先审查语句和函数。
- `Seq Scan` 可能适合小表或读取较大比例数据的查询；结合扫描/返回行数、实际耗时、缓冲访问、循环次数及调用频率判断。
- 关注估算偏差、排序溢出、重复循环、锁等待和长事务。索引设计依据过滤、连接、排序及数据分布，并计入写入维护成本。
- 迁移单独检查锁影响、执行时间、失败恢复及版本共存；项目若使用租约、队列或并发抢占，验证竞争与重试行为。

依据：[EXPLAIN](https://www.postgresql.org/docs/18/sql-explain.html)、[执行计划判读](https://www.postgresql.org/docs/18/using-explain.html)。
