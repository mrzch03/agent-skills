# Redis 检查要点

先确认实例是否共享、集群拓扑、键与集合规模、访问频率和项目限制。

- 用户请求或高频监控避免 `KEYS` 及完整键空间遍历；对象发现优先使用已维护的索引、数据库查询或事件。
- `SCAN` 分多次调用完成遍历，不等同于 `KEYS` 单次阻塞。完整遍历仍有 O(N) 成本，`MATCH` 不是索引，`COUNT` 是提示而非严格返回上限。
- 确需维护扫描时，先取得环境操作授权，设置节流和停止条件，评估共享负载；处理重复项、数据变化及拓扑范围。项目禁止扫描时遵守项目限制。
- 大集合的全量读取需要明确上界，否则使用合适的分批或索引方式；同时检查响应体、内存及轮询频率。
- 维护索引也有一致性和清理成本，要明确写入、删除、过期及重建策略；不要为消除扫描悄悄引入第二份失真的状态。

依据：[SCAN 官方语义](https://redis.io/docs/latest/commands/scan/)（2026-11-10 核对）。
