# dev-standards — 通用开发规范

本 skill 定义通用方法。**用户授权和项目规则决定具体范围、协议、分支、环境与发布方式**；不得把本 skill 当成新增发布、付费或生产写入的授权。已明确的授权不重复询问。

## 核心原则

- 先确认目标与根因，再决定实现；有更简单的方案就说明依据。改变用户目标或范围需取得确认，常规实现细节自主处理。
- 优先消除重复状态和不必要机制；保留协议边界、权限隔离、资源回收等有明确责任的机制。
- 接口和抽象服务于实际的替换、测试及跨模块边界；不机械按实现数量判断。
- 关键可行性断言给出证据；未验证的环境与假设明确标注。

## 工程约束

- 一个提交表达完整、可验证、可回退的改动；相互依赖的协议、生成代码、实现及必要测试保持一致，不按 TODO 数量机械拆分。
- 按项目的基线、保护分支和 PR/MR 规则工作；推送、合并、部署分别确认授权及结果，不把推送成功当部署完成。
- 跨模块变更遵循项目合同；记录字段、兼容范围和消费者，不为通过测试削弱架构规则。
- 文件按职责组织。文件过长时检查内聚性；长度是信号，项目有明确限制则遵守，生成文件遵循生成器规则。
- 数据变更评估正确性、锁、容量和性能；按实际数据库及版本取证，见专项规范。
- 任务状态、测试证据和未完成项可追溯；凭据不进入文档、日志、快照或提交。
