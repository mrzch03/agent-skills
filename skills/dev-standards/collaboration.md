# 协作与交接

- 用普通语言说明结果和影响；技术细节只保留能帮助判断的部分。最终汇报自包含，不要求用户读工具日志补上下文。
- 用户决定目标、重大取舍与授权；常规实现由 agent 推进。已有授权持续有效，不把每一步都变成确认。
- 系统行为应可观察。新状态或链路按用户任务提供合适的状态、回执、视图或诊断信息，不强制每次都建设独立大盘。
- 独立评审按风险使用；有授权的并行任务遵循 [dev-flow](dev-flow.md) 的边界、依赖和集成规则。
- 事实写回项目原稿；任务过程、排除的假设和证据写入任务记录；交接只保存进行中的事项、状态、下一步与链接。
- 新建项目使用 [project-skill-blueprint](../project-skill-blueprint/SKILL.md) 的 handoff 结构。已有 progress.md 等约定可继续使用，但避免追加无边界流水；迁移时保留未完成事项和证据。
- 外部平台同步按授权与项目原稿规则执行。记录请求编号等排障引用前检查敏感信息，凭据本身不得存档。
