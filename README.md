# agent-skills

工程 AI agent 的 **通用开发流程 skill 集**，另设项目系统分区。通用规则可移植，具体协议、分支、环境和发布方式由使用它的项目决定。把"怎么做需求、怎么定规范、怎么给项目沉淀认知、不确定时从哪起步"沉淀成几个高内聚、用完即丢的 skill。

## 设计哲学(为什么是这几个,而不是一个大 KB)
- **场景化、高内聚**:工序 skill 保持无状态；项目结束归档对应认知包。
- **一份事实一个家,永不复制**:通用规范只在 `dev-standards`;别的 skill 引用它,不重抄。复制 = 漂移腐烂的根源。
- **闭环、不依赖外部**:本仓自给自足,不引用第三方 skill 包;需要的能力我们自己总结成精简版。
- **能交接**:任务记录保存过程和证据，项目 `handoff.md` 保存未完成事项与下一步指针；已有项目沿用其记录约定。

## 包含的 skill
| skill | 作用 |
|---|---|
| **scenario-map** | 总入口:项目约定、风险分级与按场景找能力的路由表 |
| **dev-standards** | 通用开发规范:设计原则、风险分级、完整提交、并行集成、数据库专项和协作 |
| **feature-flow** | 标准功能与高风险变更:先定用户验收，按影响设计，开发同步测试，独立评审与集成验证 |
| **project-skill-blueprint** | 给一个项目/业务场景建"认知 skill"的骨架:目录约定 + 维护纪律 + 可复制 skeleton |
| **hotfix-flow** | 局部小改与紧急修复两条路径；紧急修复需明确授权、止损、回退及补验安排 |
| **issue-branch** | 任务、分支与 PR/MR 可追溯；遵循项目命名与验收关闭条件 |
| **codex-review** | 独立评审:结合需求、差异与验证证据，区分通过、需修改和证据不足 |
| **verify** | 带证据的验证:真跑、观察预期、留日志/截图/DB行/trace,别在没证据时说"做完了" |
| **product-design-review** | 产品交互设计与走查:从用户已有材料和目标出发，检查任务结构、直接操作、反馈恢复、上下文与冲突可视化，用完整场景验收 |

## 项目系统 skill(2026-07-03 起,本仓新增分区)
除通用骨架外,本仓也承载**我们自己的产品体系总纲**:
| skill | 作用 |
|---|---|
| **clawbox-system** | ClawBox 产品体系:使命→发展路线→产品矩阵→部署→查问题 + 跨会话迭代仪式。做方向决策/接手任何产品线先读 |

约定:体系层住这里;各项目的深度认知仍住项目自己的认知 skill(一份事实一个家)。

## 安装
```bash
./install.sh              # 软链 skills/* 进 ~/.claude/skills(默认)
./install.sh /path/to/project/.claude/skills   # 或装进某项目的 skills 目录
```
脚本链接所有目录（含项目系统分区），不会覆盖同名实体目录。仅需通用流程时按需链接对应目录；在 Codex 中使用其支持的 skills 目录，或由项目 AGENTS.md 指定读取入口。
软链指向本仓当前工作树，切分支或修改即影响使用方；共享使用时选择稳定版本，不通过项目软链修改通用库。

## 在新项目里落地
1. 装上本仓(install.sh)。
2. 在项目 AGENTS.md 或项目入口登记项目规则与技能路径，不直接改共享 `scenario-map`。
3. 按需使用 `project-skill-blueprint`，引用已有架构/合同文档；任务记录保存证据，handoff 保存指针，避免复制事实。
4. 按 `dev-standards/dev-flow.md` 判断小改、标准功能或高风险变更；界面先做产品走查，开发同步测试，按项目规则评审和交付。
5. 实现、本地测试、真实联调、合入、部署分别记录状态；通用 skill 不扩大用户授权。

## 维护约定
- 改任何 skill:**一份事实一个家,永不复制**;每篇 ≤100 行,超了拆。
- 新增一个通用场景 skill:在 `scenario-map` 路由表加一行 + 在本 README 表格加一行。
- 通用工序不写项目专属事实；项目系统分区保持独立，不能把其环境和发布规则下沉为全局要求。
